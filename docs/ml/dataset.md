# Data Sheet

## Общая информация

**Название датасета:**  
Собственный синтетический датасет для классификации интентов в русскоязычных чат-ботах (название в карточке модели не указано, помечен как custom)

**Источник:**  
Данные сгенерированы автором модели (Gleckus) и не опубликованы как отдельный датасет на Hugging Face. 

**Назначение:**  
Обучение модели классификации текста для определения намерения (интента) сообщения пользователя в русскоязычном чат-боте. Исходная модель различает 3 класса: rag, chat, followup

## Состав данных

**Объём:**  
2 877 примеров.

**Тип данных:**  
Текстовые сообщения на русском языке

**Основные поля / признаки:**  
Текст сообщения пользователя и соответствующая метка класса (rag, chat или followup). 

## Получение данных

По информации автора модели, данные синтетические — сгенерированы ИИ по шаблонам, а не собраны из реальных диалогов. 

## Предобработка
Не указана

## Ограничения

Синтетическая природа данных: примеры сгенерированы по шаблонам, а не собраны из реальных диалогов. Это может ограничивать разнообразие формулировок и снижать качество на реальных сообщениях пациентов.

Дисбаланс классов: метрики показывают, что класс followup имеет заметно более низкий Recall (0.73) по сравнению с rag (0.98) и chat (0.90) , что может указывать на недостаточное представление этого класса в данных.

Данные не относятся к медицинской тематике и не покрывают лексику, связанную с записью к врачу (специальности, симптомы, даты приёма).

Датасет содержит только метки классов. Сущности (doctorName, dateTime) в нём не размечены.

Датасет не опубликован как отдельный артефакт на Hugging Face, что затрудняет независимую проверку его состава

## Использование в проекте

Датасет не используется напрямую в проекте ИИ-бота для записи к врачу, поскольку его классы (rag, chat, followup) не совпадают с целевыми намерениями бота (make_appointment, cancel_appointment, list_appointments, unknown).

 Для реального проекта потребуется собрать и разметить собственный датасет сообщений пациентов с целевыми классами, либо дообучить модель на имеющихся данных с последующей валидацией на реальных примерах.
